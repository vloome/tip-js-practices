## Эксперименты с формой и хранилищем

| № | Прогноз | Фактический результат и объяснение |
|---:|---|---|
| 1. Пустое обязательное название | Браузер не должен отправить форму, поскольку поле имеет `required`. | Заполнить после эксперимента. |
| 2. Название из пробелов | `required` не считает строку из пробелов пустой; прикладная проверка после `trim()` должна её отклонить. | Заполнить после эксперимента. |
| 3. Тип значений `FormData` | Значения текстовых полей будут строками; `submit` будет обработан без перезагрузки страницы. | Заполнить после эксперимента. |
| 4. `localStorage` и JSON | `getItem()` возвращает строку, а `JSON.parse()` преобразует корректную JSON-строку в объект. | Заполнить после эксперимента. |
| 5. Повреждённый JSON | `JSON.parse()` выбросит исключение; его необходимо перехватить. | Заполнить после эксперимента. |

## Вывод

В работе реализованы создание и редактирование задач через HTML-форму, нативная и прикладная проверка ввода, безопасный вывод сообщений об ошибках и сохранение данных в `localStorage`. Сохранённые данные проверяются перед использованием; при повреждении JSON или несовпадении схемы приложение возвращается к исходному набору и показывает предупреждение. Фактические результаты автоматических и ручных проверок следует указать после запуска приложения.
