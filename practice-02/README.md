## 4. Модель данных и функции

* **Поля задачи:** 
  * `id` — число, безопасное целое (`Number.isSafeInteger(id)`), строго больше 0.
  * `title` — строка длиной от 1 до 100 символов после удаления краевых пробелов методом `trim()`.
  * `completed` — логическое значение (`false` по умолчанию).
  * `priority` — строка, строго одно из допустимых значений: `"low"`, `"medium"`, `"high"` (по умолчанию `"medium"`).
* **Правила валидации:** Проверяются типы аргументов, числовые диапазоны, длина названий через `.length` после `trim()`, соответствие приоритетов и уникальность идентификатора (`id`) при добавлении.
* **Назначение файлов:**
  * `src/data.js` — экспорт общего набора демонстрационных данных (`demoTasks`) и структуры индивидуального варианта.
  * `src/task-service.js` — прикладной модуль, содержащий 9 функций для создания, чтения, изменения и удаления задач без побочных эффектов (`console.log`).
  * `src/main.js` — демонстрационный исполняемый сценарий, управляющий состоянием и выводом результатов в консоль.
* **Результаты операций:**
  * При успехе операции создания или модификации возвращают объект вида `{ ok: true, task: ... }` или `{ ok: true, tasks: ... }`.
  * При обнаружении ошибок возвращается стандартный объект отказа: `{ ok: false, error: "Описание причины" }`.
  * Функции чтения возвращают найденный объект, новый отфильтрованный массив или объект сводки (`{ total, completed, pending, progress }`).

**Почему id не равен индексу:**  
`id` — это постоянный уникальный идентификатор сущности, который закрепляется за задачей навсегда и не изменяется при удалении или добавлении других элементов. Индекс же отражает текущую позицию элемента в массиве (`0, 1, 2...`) и сдвигается при любых изменениях структуры списка.

**Почему getTaskStats возвращает число, а не строку с процентом:**  
Прикладные функции должны оперировать «сырыми» числовыми данными (`number`), чтобы их можно было использовать в дальнейших математических расчетах и проверках. Форматирование в строку (например, через `.toFixed(1)`) выполняется исключительно на этапе вывода в интерфейс или консоль.

**Какие объекты копируются при изменении задачи:**  
Создаётся новый массив (через spread-оператор или методы массива), а для изменяемой задачи создаётся совершенно новый объект с обновлёнными свойствами (`{ ...task, ...updates }`). Неизменённые задачи допускается использовать повторно со старыми ссылками (поверхностное копирование), так как их свойства не затрагиваются операцией.
